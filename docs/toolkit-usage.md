# Toolkit usage by recipe

Not every recipe uses the Azure Functions Python DX Toolkit. Some are plain Azure Functions examples that depend only on the Azure Functions SDK and other third-party packages; others opt in to one or more toolkit packages. This page lists both kinds so you can find them without scanning source.

- **47 recipes** declare at least one toolkit package.
- **35 recipes** are plain Azure Functions examples (no toolkit package).

## How usage is determined

A recipe counts as using a toolkit package when its `pyproject.toml` declares that package as a dependency. This is the same definition the repository tests use for the dogfood coverage line in the docs home page, so there is one counting method. Declaring a dependency does not prove the package was exercised in a Functions host or in Azure; each recipe's `verification` level (from `recipe.yaml`) describes how it is actually tested. The levels are `docs` (documentation only), `unit` (unit tests in required CI), `func-host` (also covered by the Functions host smoke matrix in CI) and `azure` (verified against real Azure).

`scaffold_walkthrough_app` is generated by the scaffold CLI and declares the packages the generated project template pulls in (`azure-functions-validation`, `azure-functions-doctor`); it does not import them in its own source. It is counted under those declarations and is marked *CLI-generated* below.

Print the counts from the repository root:

```bash
python scripts/check_ecosystem_counts.py --print
```

`make check` (through `make generated-check`) runs `python scripts/check_ecosystem_counts.py`, which fails when the counts below or the ecosystem table in `README.md` and its translations differ from what the recipes declare. `azure-functions-scaffold` is not counted that way: it is a CLI that generates projects, and no recipe declares it.
